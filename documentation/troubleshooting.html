Troubleshooting

Common problems and how to solve them. When in doubt, build with logs to see what the firmware is doing.

Building

The build fails after it worked before

The build folder was created for another keyboard, another board, or with a different value of RGB or LOGS. Rebuild from scratch:

west build -p always -b nrf52840 -- -DKEYBOARD=miguelio/mk60v1

One example is an error that mentions ws2812 when the folder was last used for a keyboard with RGB. See Building.

"KEYBOARD not defined"

The -DKEYBOARD=… argument is missing. It goes at the end of the command, after the -- separator.

"RGB enabled … but RGB_PORT/RGB_PIN/RGB_LEDS not defined"

keyboard.h has #define RGB true without the three numeric defines that describe the LED chain. See RGB lighting.

Errors about rgb_on or spi_dev

The keyboard enables POWER_EXT without RGB. The external power pin can only be used together with the RGB lighting.

Kconfig warnings in the dongle build

Warnings about BT_PERIPHERAL_PREF_* symbols are expected and harmless.

Flashing

The bootloader drive does not appear

  • Double-tap the reset button quickly; a single press only restarts the firmware.
  • Use a USB cable that carries data. Many cables only charge.

Bluetooth

The keyboard is not in the Bluetooth list

  • Press a key. After a long time unused, Bluetooth is off until the keyboard is woken up.
  • If it is paired with another host that is nearby, that host reconnects first and the keyboard stops being visible, because it accepts one connection at a time. Press HID_BT_CLEAR to forget that host.

The host shows the keyboard but cannot connect

This happens after a HID_BT_CLEAR, because the host still remembers the old pairing. Remove BMK Keyboard from the Bluetooth list of the host and pair again.

The keyboard takes a few seconds to reconnect

After a disconnection the keyboard advertises slowly to save battery, so the host needs a little longer to find it. This is the expected behaviour. See Bluetooth.

Nothing is typed over Bluetooth while the cable is plugged in

With USB connected, keys are sent over USB only. Unplug the cable to type over Bluetooth.

USB dongle

The dongle does not connect to the keyboard

  • The keyboard is paired with a computer. Press HID_BT_CLEAR on the keyboard so it becomes free.
  • The keyboard has turned Bluetooth off. Press a key to wake it up.
  • Another free keyboard running BMK is nearby and the dongle connected to that one.

The keyboard stopped working with the dongle after pairing it with a computer

A paired keyboard no longer shows the free mark, so the dongle ignores it. Press HID_BT_CLEAR to go back to the dongle.

Keys

A key sends the wrong character

The entry is at the wrong position in the keymap. Positions follow the electrical matrix: row * MATRIX_COLS + column. See Keymaps and layers.

A whole row or column does nothing

Check its pin in keyboard.c against the schematic, including the port: P0(n) and P1(n) are different pins.

No key works at all

The diodes may face the other way. Declare the rows of the PCB as columns and the columns as rows. See Adding a keyboard.

Double characters

Raise DEBOUNCE_PRESS and DEBOUNCE_RELEASE in keyboard.h.

The keyboard stays on a layer

The position of the FN_MO key must be HID_KEY_TRANS on the layer it activates. With HID_KEY_NONE there, the release of the key is not seen.

A tap-hold key acts as a modifier when tapped

Raise TAP_HOLD_PRESS_DELAY. See Tap-hold.

The encoder works backwards

Swap its two keycodes in the keymap or its two pins in keyboard.c.

Lighting

The LEDs do not light up

  • Check RGB_PORT, RGB_PIN and RGB_LEDS.
  • If the LEDs are fed through a switch or regulator, enable POWER_EXT and set pin_power_ext.
  • Rebuild with -p always after changing any of them.

The LEDs stay on when the keyboard sleeps

The firmware switches them off through the external power pin. A PCB without it keeps the LEDs lit. See RGB lighting.
