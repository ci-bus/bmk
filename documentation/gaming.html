Gaming mode

Gaming mode scans the matrix much more often and sends each key press without waiting for the debounce, trading battery life for a lower delay between pressing a key and sending it.

Switching it on and off

Put these two keycodes somewhere in your keymap, usually on a secondary layer:

KeycodeAction
HID_GAMING_ONEnables gaming mode.
HID_GAMING_OFFDisables gaming mode.

Gaming mode is always off when the keyboard starts. Switching it releases every key that was held.

What changes

NormalGaming mode
Pause between matrix scansCYCLE_DELAY (1000 µs by default)GAMING_CYCLE_DELAY (100 µs by default)
Debounce of a key pressDEBOUNCE_PRESS (5 ms by default)GAMING_DEBOUNCE_PRESS (0 ms by default): the press is sent on the first reading
Debounce of a key releaseDEBOUNCE_RELEASE (15 ms by default)GAMING_DEBOUNCE_RELEASE (10 ms by default)
GUI keys (Windows key)Work normallyIgnored, so they cannot take you out of a full-screen game

Both GUI keys are ignored, also when they are the hold action of a tap-hold key. The other modifiers keep working.

The tap-hold times are recalculated for the new scan rate, so they keep the same duration in milliseconds.

With a press debounce of 0, contact bounce is still filtered by the release debounce: once a press is sent, the key is not released until it has read as released for GAMING_DEBOUNCE_RELEASE. If a keyboard produces unwanted or repeated key presses in gaming mode, raise GAMING_DEBOUNCE_PRESS to 1 or more, or raise GAMING_DEBOUNCE_RELEASE.

With the default values the pause between scans is ten times shorter, so the processor rests less and the battery drains faster. Switch gaming mode off when you finish playing.

Options

Set them in keyboard.h:

OptionDefaultMeaning
CYCLE_DELAY1000Pause in µs between two matrix scans in normal mode.
GAMING_CYCLE_DELAY100Pause in µs between two matrix scans in gaming mode.
GAMING_DEBOUNCE_PRESS0Time in ms a key must read as pressed before the press is sent in gaming mode.
GAMING_DEBOUNCE_RELEASE10Time in ms a key must read as released before the release is sent in gaming mode.

With the default GAMING_CYCLE_DELAY, keep both gaming debounce times at 25 ms or less: the debounce counter of a key holds up to 255 scan cycles.
