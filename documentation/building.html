Building

One command builds the firmware. You choose the board with -b and the keyboard with -DKEYBOARD.

Build a keyboard

Run the build from the app folder, inside the container:

cd app
west build -p auto -b nrf52840 -- -DKEYBOARD=miguelio/mk60v1

or, for a PCB that carries an nRF52833 module:

west build -p auto -b nrf52833 -- -DKEYBOARD=miguelio/mk60v2

The keyboard and the board are independent choices: the same keyboard can be built for either board, and -b must match the module soldered on your PCB.

The result is build/zephyr/zephyr.uf2, ready to be flashed.

What each part means

PartMeaning
-b nrf52840The board: nrf52840 or nrf52833. It must match the chip on your PCB.
-DKEYBOARD=miguelio/mk60v1The keyboard folder inside app/keyboards, or dongle for the USB dongle.
-p autoLets west decide whether the build folder must be cleaned first. Use -p always to force it.
-d <folder>Optional. Builds into another folder instead of build.

Build the USB dongle

west build -p auto -b nrf52840 -d build-dongle -- -DKEYBOARD=dongle

The result is build-dongle/zephyr/zephyr.uf2. Keep a dedicated build folder for the dongle, as in the command above, so it does not mix with a keyboard build.

When to force a clean build

A build folder remembers the configuration files and overlays it was created with. Add -p always whenever you reuse the same folder after one of these changes:

  • You build a different keyboard or switch between a keyboard and the dongle.
  • You build for a different board.
  • You change RGB or LOGS in keyboard.h (or LOGS in dongle.h).
west build -p always -b nrf52840 -- -DKEYBOARD=miguelio/mk60v1

Changes to the keymap or to any other option only need a normal build.

If you work on several targets, give each one its own folder with -d. Every folder keeps its own configuration and rebuilds are faster.

What the build reads from keyboard.h

Most options in keyboard.h are plain C defines used by the source code. Two of them also change how the project is configured, and the build system reads them directly from the file:

DefineEffect on the build
#define RGB trueAdds the LED strip driver and its devicetree overlay, using RGB_PORT, RGB_PIN and RGB_LEDS. The build stops with an error if any of the three is missing.
#define LOGS trueAdds the USB serial console used for logs.

Write these lines exactly in this form, with a literal true and numeric values, because they are matched as text.

Warnings you can ignore

The dongle build prints Kconfig warnings saying that some BT_PERIPHERAL_PREF_* symbols were assigned a value but got a different one. They come from keyboard settings that do not apply to the dongle and are harmless.
