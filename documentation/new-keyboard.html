Adding a keyboard

A keyboard is a folder with three files: the options, the pins and the keymap. No other part of the firmware has to be touched.

Before you start

You need to know, from the schematic of the PCB:

  • Which chip it uses: nRF52840 or nRF52833.
  • Which pin of the chip each column and each row of the matrix is connected to.
  • The direction of the diodes.
  • The pins of the encoder, of the LED data line and of the external power switch, if the PCB has them.

Matrix wiring

The firmware drives one column high at a time and reads the rows, which have their internal pull-down resistors enabled. Current therefore flows from the column, through the switch and the diode, into the row:

column pin ──── switch ──── diode ▶| ──── row pin

The cathode of each diode, the side marked with a line, must face the row. A PCB with the diodes the other way round can still be used by declaring its rows as columns and its columns as rows.

1. Create the folder

Keyboards live in app/keyboards/<vendor>/<keyboard>. The easiest start is to copy an existing one:

cp -r app/keyboards/miguelio/mk60v2 app/keyboards/myname/mykeyboard

2. keyboard.h: options

#ifndef KEYBOARD_H
#define KEYBOARD_H

#include "bmk.h"

#define MATRIX_COLS 3
#define MATRIX_ROWS 2
#define LAYERS 2
#define ENCODERS 0

extern const uint16_t layers[LAYERS][MATRIX_COLS * MATRIX_ROWS + ENCODERS * ENCODER_PINS];

#endif

The four defines shown are required. Everything else is optional and listed in Configuration options. Add here what your PCB has:

The PCB hasAddDetails
A rotary encoder#define ENCODERS 1Encoders
WS2812 LEDsRGB, RGB_PORT, RGB_PIN, RGB_LEDSRGB lighting
A switchable supply for the LEDs#define POWER_EXT trueExternal power

3. keyboard.c: pins

#include "keyboard.h"

const uint16_t pin_cols[MATRIX_COLS] = {
    P0(28),
    P0(15),
    P1(0),
};

const uint16_t pin_rows[MATRIX_ROWS] = {
    P0(13),
    P0(24),
};
  • P0(n) is pin n of port 0 and P1(n) is pin n of port 1: P1(9) is the pin called P1.09 in the datasheet.
  • pin_cols and pin_rows need exactly MATRIX_COLS and MATRIX_ROWS entries. Their order defines the column and row numbers used by the keymap.

Optional pins

Add the encoder pins when ENCODERS is 1 and the external power pin when POWER_EXT is enabled. Leave them out otherwise.

const uint16_t pin_encoders[ENCODERS * ENCODER_PINS] = {
    P0(6),
    P0(5),
};

const uint16_t pin_power_ext = P1(9);

Modules such as the E73 have their own pin numbers. Use the table in the module manual to translate each module pad to the pin name of the chip (P0.xx or P1.xx), which is what the firmware needs.

Pins to keep free

  • P0.18 on keyboards with RGB: it is taken by the peripheral that generates the LED data.

One keyboard, two chips

A PCB can usually take a module with either chip. The two chips do not have the same pins: the nRF52833 has no P1.10 to P1.15, so a module pad that is one pin on the nRF52840 can be a different pin on the nRF52833. Where a pad differs, select the pin at compile time:

#if defined(CONFIG_SOC_NRF52833_QIAA)
#define COL4_PIN P1(5)
#else
#define COL4_PIN P1(13)
#endif

4. keymap.c: keys

One keycode per matrix position, row by row, for every layer. See Keymaps and layers for the format and Keycodes for the values.

A good first keymap is a single layer where every position sends a different letter or number. Flash it, press every switch and note which position each one reports. Then write the real keymap.

5. Build and test

cd app
west build -p always -b nrf52840 -- -DKEYBOARD=myname/mykeyboard

Use -b nrf52833 instead if the PCB carries an nRF52833 module.

Flash the result as described in Flashing and check:

  • Every switch sends its key, over USB and over Bluetooth.
  • The encoder turns in the expected direction.
  • After ten seconds without typing, a key on each row wakes the keyboard up.

If something does not behave as expected, build with logs and see Troubleshooting.
