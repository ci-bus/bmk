Keymaps and layers

The keymap decides what every switch sends. It lives in the keymap.c file of each keyboard folder.

Structure of keymap.c

The keymap is a single array called layers. Each layer lists one keycode per matrix position, followed by two keycodes per encoder:

#include "keyboard.h"

const uint16_t layers[LAYERS][MATRIX_COLS * MATRIX_ROWS + ENCODERS * ENCODER_PINS] = {
    {
        HID_KEY_ESC,   HID_KEY_1,    HID_KEY_2,    HID_KEY_3,
        HID_KEY_TAB,   HID_KEY_Q,    HID_KEY_W,    HID_KEY_E,
        HID_KEY_LCTRL, HID_KEY_LGUI, HID_KEY_SPACE, FN_MO(1),
        HID_KEY_VOLUME_DOWN, HID_KEY_VOLUME_UP
    },
    {
        HID_BT_CLEAR,  HID_KEY_F1,   HID_KEY_F2,   HID_KEY_F3,
        HID_KEY_NONE,  HID_KEY_NONE, HID_KEY_UP,   HID_KEY_NONE,
        HID_KEY_TRANS, HID_KEY_NONE, HID_KEY_RGB_TOGGLE, HID_KEY_TRANS,
        HID_KEY_NONE, HID_KEY_NONE
    }};

This example is a keyboard with 4 columns, 3 rows, one encoder and two layers.

Order of the keys

Keys are written row by row. The position of a key in the array is:

index = row * MATRIX_COLS + column

The rows and columns are the electrical ones defined in keyboard.c, which do not always match the physical rows of the keyboard. If a key sends the wrong character, find its row and column pins and fix the entry at that index.

After the last matrix row come the encoder entries: two per encoder, one for each direction. See Encoders.

Empty positions

Matrix positions without a switch must still have an entry. Use HID_KEY_NONE.

Layers

The number of layers is set with LAYERS in keyboard.h. Layer 0 is the one active when the keyboard starts.

KeycodeBehaviour
FN_MO(n)Momentary: layer n is active while the key is held. Releasing it returns to the previous layer.
FN_TO(n)Switch: layer n becomes active when the key is released and stays active. Put a FN_TO(0) on that layer to come back.
HID_KEY_TRANSTransparent: the key does what the layer below does.
HID_KEY_NONENothing: the key is ignored on this layer.

On the layer you reach with FN_MO(n), put HID_KEY_TRANS in the same position as the FN_MO(n) key, so the key release is still seen and the layer is left.

When the active layer changes, every key that was held is released on the host. This prevents a key from staying pressed if it means something else on the new layer.

What a key can be

  • A standard key, a modifier or a media key. See Keycodes.
  • A tap-hold key: a keycode when tapped, a modifier when held.
  • A layer key, as described above.
  • A firmware action: Bluetooth, RGB, sleep, gaming mode, reset. They are listed in Keycodes.

Limits

  • Up to six standard keys can be held at the same time, plus any combination of the eight modifiers.
  • Up to six media keys can be held at the same time.

Applying changes

After editing keymap.c, build and flash again. A normal build is enough; no clean build is needed.
