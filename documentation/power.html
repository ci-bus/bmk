Sleep and power

On battery the keyboard lowers its consumption in steps as it stays idle. A key press always brings it back.

Power states

StateEnteredWhat happens
AwakeOn any key press or encoder stepThe matrix is scanned continuously, every CYCLE_DELAY microseconds.
SleepAfter SLEEP_TIMEOUT seconds without activity (10 by default)Scanning stops and the processor waits for a key press. The Bluetooth connection is kept, so typing resumes at once.
Deep sleepAfter DEEP_SLEEP_TIMEOUT minutes asleep (30 by default)Bluetooth is turned off. The next key press turns it on again and the host reconnects.

Details of each step

  • The keyboard does not sleep while a key is held or while the USB cable is connected.
  • While it is advertising fast and waiting for a host, the keyboard stays awake for SLEEP_TIMEOUT_ADV seconds (300 by default) instead of SLEEP_TIMEOUT.
  • When it falls asleep, the battery measurement and the RGB animation stop, and the external power pin is switched off.
  • Any key and the encoder wake the keyboard up. The key that wakes it is processed normally.

Other ways into deep sleep

  • The key HID_DEEP_SLEEP: turns Bluetooth off as soon as the key is released. Useful before putting the keyboard in a bag.
  • A lost connection: after a disconnection the keyboard advertises slowly for SLEEP_TIMEOUT_ADV seconds. If no host connects in that time, Bluetooth is turned off. See Bluetooth.

Deep sleep does not restart the firmware. Waking up keeps the active layer and the rest of the keyboard state.

Timing options

Set them in keyboard.h:

OptionDefaultUnitMeaning
SLEEP_TIMEOUT10sIdle time before sleep.
SLEEP_TIMEOUT_ADV300sIdle time before sleep while advertising fast, and duration of the slow advertising after a disconnection.
DEEP_SLEEP_TIMEOUT30minTime asleep before Bluetooth is turned off.
CYCLE_DELAY1000µsPause between two scans of the matrix while awake. A larger value lowers consumption and raises latency.

External power

Some PCBs feed power-hungry parts, such as the LEDs, from a regulator or switch controlled by a pin of the microcontroller. BMK can drive that pin so those parts draw nothing while the keyboard sleeps.

Enable it in keyboard.h and give the pin in keyboard.c:

#define POWER_EXT true
const uint16_t pin_power_ext = P1(9);

The pin is driven high to switch the power on and low to switch it off.

POWER_EXT can only be enabled together with RGB. A keyboard with POWER_EXT and without RGB does not compile.

Behaviour

SituationPin
Keyboard asleepOff.
Keyboard awake, POWER_EXT_RGB_LINKED trueFollows the RGB lighting: on when the LEDs are on, off when they are off.
Keyboard awake, POWER_EXT_RGB_LINKED falseFollows its own state, which starts as POWER_EXT_ON and changes with HID_KEY_POWER_ON and HID_KEY_POWER_OFF.

With POWER_EXT_RGB_LINKED true, HID_KEY_POWER_ON and HID_KEY_POWER_OFF also turn the RGB lighting on and off.

Options

OptionDefaultMeaning
POWER_EXTfalseEnables the external power pin.
POWER_EXT_RGB_LINKEDtrueTies the pin to the state of the RGB lighting.
POWER_EXT_RGB_DELAY5Time in ms to wait after switching the power on before sending data to the LEDs.
POWER_EXT_ONtrueInitial state of the pin when it is not linked to the RGB lighting.
